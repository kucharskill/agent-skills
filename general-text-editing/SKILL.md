# General Text Editing

## Scope

For an existing text, default to a light edit. Keep the author's voice, register, structure, and wording wherever they serve the reader. Rewrite more deeply when the user requests it or the agreed outcome requires it. For an audit, point out specific passages and explain what to change. When drafting from notes or sources, draft from the supplied material and apply these editing checks before delivery. Use the user's writing sample to guide tone and rhythm when available.

## Editing rules

- Preserve facts, numbers, quotations, citations, definitions, and the scope and certainty of each claim. Keep conditions, exceptions, obligations, and other qualifications. Mark substantive gaps or ambiguities for the user rather than guessing.
- Use precise technical, methodological, scientific, and legal terminology. Keep the same term for the same concept and retain established formulations with a defined meaning. Repeat a precise term whenever needed. Revise the surrounding sentence if the repetition makes the prose awkward. Flag a suspected terminological error unless available evidence and the requested scope support correcting it.
- Remove filler, inflated wording, repeated signposting, and formulaic constructions when they make the text sound automated. Improve rhythm where it helps comprehension. Keep the author's natural phrasing and adapt the formality to the audience and purpose.
- Leave out routine summaries, opening recaps, and closing takeaways that repeat what the reader already knows. Include a conclusion when the user asks for one, the genre requires it, or it provides necessary synthesis, a decision, or a next step.
- In edited substantive prose, replace em and en dashes with a plain hyphen where appropriate, or recast the sentence. Preserve punctuation in exact quotations and other verbatim material. Keep mathematical minus signs, code, identifiers, and other notation where the character carries meaning.

## Supplementary skills

Use guidance from the following installed helpers only where it fits the context and language of the text. Apply general principles of clarity, specificity, rhythm, and structure across languages. Match word lists, idioms, syntax, and punctuation advice to the target language and register.

- `$humanizer-pl` for Polish calques, idioms, syntax, and characteristic phrasing. [Source](https://github.com/mateuszkozlowski/codex-humanizer-pl)

- `$humanizer:humanizer` (also listed as `$humanizer` in standalone installs) for structural patterns and voice matching when a deeper edit is in scope. [Source](https://github.com/blader/humanizer)

Look up these identifiers in the current skill list and use the listed local path to read the SKILL.md of each helper you select. Use the source link to distinguish skills with similar names. Follow the user's instructions and the editing rules above when a helper suggests adding details, changing terminology, or rewriting beyond the agreed scope.

When using this skill, check which of the listed helpers are installed. If any are missing, ask the user once per task whether to install them and name every missing helper. Install only the helpers the user explicitly approves. Continue with this skill's rules for work that can proceed while awaiting a reply or if the user declines.
